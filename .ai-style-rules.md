# Conta Perfume style rules

## Golden Files

- `app/conta-app.tsx`: navigation, capability checks, shared command lifecycle, and composition of the main workspaces.
- `app/api/command/route.ts`: perfume-aware authorization and routing wrapper. Keep it small.
- `app/api/command/base-route.ts`: perfume-only commands.
- `app/api/command/core-route.ts`: accounting-core commands synchronized from Conta Offline.
- `app/perfume-divisions.tsx` and `app/perfume-invoices.tsx`: perfume workflows and local validation.
- `app/perfume-ui-fixes.css` and `app/perfume-layout-safety.css`: perfume-specific visual system and viewport containment.
- `app/i18n/messages.ts`: Arabic source strings and their French translations.
- `tests/*.test.mjs`: structural and regression contracts used by this repository.

## Naming & State-Control Rules

- Use existing domain names (`decant`, `bottle`, `partial`, `perfumeLots`) instead of introducing synonyms.
- Keep React state local to the workspace that edits it; derive totals and filtered collections with `useMemo` when the surrounding code does so.
- Route every business mutation through `run` and the `/api/command` idempotent transaction path.
- Add general accounting commands to `core-route.ts`, perfume commands to `base-route.ts`, and only authorization/routing concerns to `route.ts`.
- Check UI capabilities with the existing `can(...)` pattern and enforce the same capability again in the API.
- Reuse `tr(...)`, `money(...)`, `quantity(...)`, `FramedSection`, existing controls, and `.erp-*` table styles.
- Keep Arabic and French behavior direction-safe; prefer logical CSS properties such as `inset-inline-*` and `margin-inline-*`.
- Desktop workspaces stay inside the fixed app frame. Forms and actions remain visible; growing tables own their scrollbars.
- Preserve audit history: edits and voids create explicit business effects instead of rewriting posted history.

## DONTs

- Do not replace the perfume command wrapper with Conta Offline's monolithic route.
- Do not remove perfume document kinds, reports, permissions, translations, identity, or desktop data isolation during a core sync.
- Do not place perfume-only styling back into `globals.css`; core synchronization may replace it.
- Do not add a second visual system, one-off colors, or unscoped global selectors for perfume pages.
- Do not mutate stock, balances, or posted documents directly from UI components.
- Do not use browser-native confirmation flows when the surrounding workspace already supplies an application confirmation primitive.
- Do not hide overflow at a workspace boundary unless every growing child has its own reachable scrollbar.
- Do not add untranslated user-visible strings or assume left-to-right layout.
